title: LSB steganography
---

Got curious on how hackers embed secret messages inside medias like images, videos and audio files and found out about steganography.

Steganography is the practice of hiding messages, files, scripts or datas inside a normal ordinary file or a physical medium such that the very existence of there being a message is hidden.

The concept is very similar to cryptography but the whole difference is that during encryption, even if it is also unreadable, you know about the existence of a message.

Steganography also comes in different forms depending on the media you are working with and each one of them their own way unique way of hiding messages.
For example: Image steganography, Audio steganography, Video steganography, etc.

But for this project, since we are just exploring, we are going to start with the image steganography and it's simplest algorithm: **Least Significant Bit (LSB) steganography**

### **The key idea**
Every color channel of a pixel is a byte, for example `255 = 11111111`. The rightmost bit is the **least significant bit**. It only changes the value by 1. Flipping it turns `255` into `254`, a difference no human eye can see.

So if we overwrite the last bit of many bytes with the bits of our message, the image looks identical, but it now carries a hidden payload.

### **Prerequisite knowledge**

**Raster images.** Images come in many kinds (raster, vector, voxel, ...). We only care about _raster_ images: Your typical pixelated images where each pixel holds a color.

**Color models.** A color model defines how a pixel's color is stored. RGB is the most common; others include RGBA, BGR, CMYK and OKLCH. An RGB image is just a flat run of channel values:

```txt
(R, G, B), (R, G, B), (R, G, B), ...
```

Models can be converted into each other, but sometimes information is lost. Converting RGBA to RGB drops the alpha channel, and converting back can't recreate what was thrown away. We'll convert whatever image we're given to RGB.

**Bit depth.** This is how many values one channel can hold. An 8-bit channel holds 256 values (0-255). More bits means more precision. We'll use 8 bits per channel, i.e. RGB8.

**Lossless vs. lossy formats.** This one matters a lot. LSB only works if the pixel values you wrote are the ones you read back. PNG is lossless, so that holds. JPEG is lossy: it recompresses pixels and will happily destroy your hidden bits. Always save the output as PNG (or another lossless format).

### Working Mechanism:
**1. Turn the message into bits.**
```txt
"Hello World" -> 01001000 01100101 01101100 01101100 01101111 00100000 01010111 01101111 01110010 01101100 01100100
```

**2. Pick where the bits go.**
In memory, our image is just bytes:
```txt
(00001111 00001111 00001111), (00001111 00001111 00001111), ...
```

We'll overwrite the last bit of each byte, one message bit per byte:
```txt
(0000111[?] 0000111[?] 0000111[?]), (0000111[?] 0000111[?] 0000111[?]), ...
```

You could use the last 2 or 3 bits of each byte instead. That fits more message, but the changes become easier to spot. We'll stay with one.

**3. Store the length first.**
The decoder needs to know where the message ends. So before the message we write its length as a 32-bit unsigned integer (`u32`, big-endian). "Hello World" is 11 bytes:
```txt
00000000 00000000 00000000 00001011
```

These 32 bits go into the last bits of the first 32 channel bytes. For each bit we overwrite the channel's last bit:
```txt
channel byte:  00001111
message bit:         0
result:        00001110   (changed)

channel byte:  00001110
message bit:         0
result:        00001110   (already matched, unchanged)
```

In code this is one expression: clear the last bit, then OR in the message bit.
```rust
byte = (byte & !1) | bit;
```

**4. Store the message.**
Same thing, continuing right after the length. The first bit of `H` (`01001000`) lands in channel byte number 33, the second bit in number 34, and so on. 11 message bytes need 88 channel bytes, plus 32 for the length, so "Hello World" touches only the first 120 channel bytes of the image.

**Decoding** is the same process in reverse: read the last bit of the first 32 channel bytes, rebuild the length, then read `length * 8` more last bits and pack them back into bytes.

#### How much can you hide?
One bit per channel byte means an RGB image holds `width * height * 3 / 8` bytes, minus 4 for the length header. A 1920x1080 image fits about 777 KB.

### The code
Here is the full code. It needs the `image` crate.
```rust
use image::ImageReader;
use std::error::Error;
use std::io;
use std::str::from_utf8;

fn main() -> Result<(), Box<dyn Error>> {
    // encoding part
    let image = ImageReader::open("Saturn.png")?.decode()?;
    let (width, height) = (image.width(), image.height());
    let mut raw = image.to_rgb8().into_raw();

    let mut input = String::new();
    io::stdin().read_line(&mut input)?;
    let message = input.trim().as_bytes();

    let mut payload = (message.len() as u32).to_be_bytes().to_vec();
    payload.extend_from_slice(message);

    if raw.len() < payload.len() * 8 {
        return Err("Message is too big".into());
    }
    let mut i = 0;
    for byte in payload.iter() {
        for bit in 0..8 {
            let msg_bit = (byte >> (7 - bit)) & 1;
            // clear the least significant bit, then set it to the message bit
            raw[i] = (raw[i] & !1) | msg_bit;
            i += 1;
        }
    }

    image::save_buffer("out.png", &raw, width, height, image::ColorType::Rgb8)?;

    // decoding part
    let altered = ImageReader::open("out.png")?.decode()?;
    let raw = altered.to_rgb8().into_raw();
    let last_bits: Vec<u8> = raw[..32].iter().map(|&x| x & 1).collect();
    let mut result = [0u8; 4];
    for (chunk_idx, chunk) in last_bits.as_chunks::<8>().0.iter().enumerate() {
        let mut byte = 0u8;
        for (bit_idx, &value) in chunk.iter().enumerate() {
            byte |= (value & 1) << (7 - bit_idx);
        }
        result[chunk_idx] = byte;
    }
    let length = u32::from_be_bytes(result) as usize;
    // cast before multiplying so a corrupt length can't overflow
    if raw.len() < 32 + length.saturating_mul(8) {
        return Err("Index out of bounds".into());
    }
    let lsb: Vec<u8> = raw[32..(32 + length * 8)]
        .iter()
        .map(|&x| x & 1)
        .collect();
    let mut result: Vec<u8> = Vec::with_capacity(length);
    for chunk in lsb.as_chunks::<8>().0 {
        let mut byte = 0u8;
        for (bit_idx, &value) in chunk.iter().enumerate() {
            byte |= (value & 1) << (7 - bit_idx);
        }
        result.push(byte);
    }
    let msg = from_utf8(&result)?;
    println!("message: {}", msg);
    Ok(())
}
```

Run it, type `Hello World`, and you should get `message: Hello World` back from `out.png`

### Limitations
- **It's fragile.** Resizing, cropping, screenshotting or converting to JPEG wipes the message out.
- **It's detectable.** Overwriting LSBs with message bits makes the low bits statistically "too random". Tools using chi-square tests or RS analysis can flag such images, even though your eyes can't.
- **It's not encrypted.** Anyone who knows the scheme can read the message. Hiding is not the same as protecting.

### Possible improvements
- **Encrypt the message** before embedding, so that finding it isn't enough to read it.
- **Randomize the positions.** Instead of writing bits in order, shuffle the channel bytes using a PRNG seeded from a password. This spreads the changes over the whole image and makes the statistics much harder to spot.
- **Spread the payload.** Don't pack everything at the top of the image; a small message only altering the first rows is easier to detect.
- **Use adaptive embedding.** Hide bits preferably in noisy or textured regions, where changes blend in, not in flat areas like a clear sky.
- **SIMD and parallelism** for large images.
