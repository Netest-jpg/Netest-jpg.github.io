Canny Edge Detection is a traditional computer vision algorithm used for capturing the structural signatures inside an image. More accurately, this algorithm identifies boundaries inside an image where the brightness changes drastically. This is important because this algorithm is mainly used as a preprocessing step for higher-level abstractions such as contour detection, feature extraction, texture analysis and more.

This week, I decided to implement the algorithm by myself in Rust using the image crate. While I could've just used Python OpenCV's Canny function, I am building this project purely to understand the algorithm's working mechanism and document the things I learn along the way.

**Note: The code is not fully optimized. A lot of optimization is possible. Please use it for learning purposes only. I might optimize a little here and there. To see the latest version, visit the source code on GitHub linked at the end.**

## Working Mechanism:

### 1. **Grayscale conversion and Gaussian Blurring**:

First, we load our image.

```rust
    let image = ImageReader::open("Mona_Lisa.jpg")?.decode()?; // loads image
```

I am going to be using the following image for our algorithm:

![Mona Lisa]({{ '/assets/image/canny/Mona_Lisa.jpg' | relative_url }})

Canny Edge Detection only works with the brightness values of the image. Therefore, we first need to reduce the multiple channels of the image to a single channel.

```rust
    let gray = image.to_luma8(); // converts the image into grayscale
```

![grayscale]({{ '/assets/image/canny/02_grayscale.png' | relative_url }})

Digital images can contain a lot of lighting noise that creates small fake changes in pixel intensity. Since the algorithm measures sharp changes in brightness, it is highly sensitive to this noise and can produce false edges. To counteract this, we apply a Gaussian blur to smooth the noise out.

```rust
    let gray = image::imageops::blur(&gray, 5.0); // blurs the image using Gaussian blur. Here: 5.0 is the value for the std deviation.
```

![Blur]({{ '/assets/image/canny/03_blurred.png' | relative_url }})

**Why Gaussian Blur and not another blurring algorithm?**

There are a few reasons:

- A Gaussian kernel falls off smoothly with no hard cutoff, so it doesn't introduce blocky artifacts the way a box blur can.
- It treats all directions equally, so it doesn't favor horizontal edges over vertical ones.
- Canny's original analysis showed that the best filter for detecting step edges is very close to the first derivative of a Gaussian. Gaussian smoothing followed by a gradient operator (Sobel, in our case) is a practical approximation of that.

**Why use 5 as the sigma value and not 1 or 6 or whatever?**

There is no universally accepted method for choosing the right standard deviation for a Gaussian blur. Therefore, I chose 5 solely through empirical testing. This number is a free parameter, so it can vary depending on what you want to capture in the final image. A larger value removes more noise but also washes out fine detail, and a good value also depends on the resolution of your image.

**Note: If you intend to use my code, you may need to adjust this value yourself to best fit your own input image.**

**What if we skip Gaussian Blur?**

### 2. Gradient Calculation

In this step, we convolve our image using the Sobel operator to calculate the gradient intensity in the horizontal (Gx) and vertical (Gy) directions for each pixel. We then use these two values to calculate the gradient magnitude and gradient direction for each pixel.

Before we can convolve, we have a small problem. When convolving, the kernel needs a full neighborhood of pixels around the target pixel to compute its output. But the outermost pixels of our image don't have a full neighborhood. Example:

```txt
1  2  3
4  5  6
7  8  9
```

Here, 1, 2, 3, 4, 6, 7, 8 and 9 don't have complete neighborhoods. Only 5 does. Because of this, we can't convolve our image just yet.

To fix this, we perform replicate padding.

```txt
 1  1  2  3   3
 1  1  2  3   3
 4  4  5  6   6
 7  7  8  9   9
 7  7  8  9   9
```

We extend the border by copying the outermost pixel values outward. This maintains the natural continuity of the boundary and prevents artificial edges, which matters for the reason explained in the question at the end of this section.

To perform this, we take the raw values of our image, its height and width, and feed them into this function that I wrote:

```rust
#[inline]
fn edge_padding(src: &[u8], width: usize, height: usize) -> Vec<u8> {
    let pw = width + 2;
    let mut slate = Vec::with_capacity(pw * (height + 2));
    for y in 0..height + 2 {
        let sy = y.saturating_sub(1).min(height - 1);
        let row = &src[sy * width..(sy + 1) * width];
        slate.push(row[0]);
        slate.extend_from_slice(row);
        slate.push(row[width - 1]);
    }
    slate
}
```

```rust
    let (height, width) = (gray.height() as usize, gray.width() as usize);
    let padded = edge_padding(gray.as_raw(), width, height);
```

Now, we are ready to begin our calculation. The Sobel operator has two kernels to convolve our image with, so we define both:

```rust
    #[rustfmt::skip]
    let gx_kernel: [i8; 9] = [
        -1, 0, 1,
        -2, 0, 2,
        -1, 0, 1
    ];
    #[rustfmt::skip]
    let gy_kernel: [i8; 9] = [
        -1, -2, -1,
        0, 0, 0,
        1, 2, 1
    ];
```

**Note: We are using the Sobel operator, but it is possible to swap it for another 3x3 gradient operator such as Prewitt or Scharr (if you do, recheck the value ranges discussed below). Not every edge filter is a drop-in replacement: Roberts Cross uses 2x2 kernels, which don't fit our 3x3 padding scheme, and DoG (Difference of Gaussians) approximates a second derivative, which is a different kind of edge detector than a first-derivative gradient.**

Now we feed the padded image, the height, the width and the two kernels into the function I wrote for the gradient calculation.

```rust
    let (raw_magnitude, raw_direction) =
        calculate_gradients(&padded, width, height, &gx_kernel, &gy_kernel);
```

#### Explanation of calculate_gradients()

Declaring starting variables:

```rust
    let pw = width + 2; // padded width
    let mut magnitude = Vec::with_capacity(width * height); // vector to store the squared gradient magnitude of each pixel
    let mut direction = Vec::with_capacity(width * height); // vector to store the gradient direction of each pixel
```

Then we loop over each pixel in the image. For each one, we calculate the horizontal gradient Gx and the vertical gradient Gy, square both and sum them to get the squared gradient magnitude, calculate the gradient direction, and map the direction (theta) to one of 0, 45, 90 or 135:

```rust
    for i in 0..(width * height) {
        let x = i % width; // column index of the pixel
        let y = i / width; // row index of the pixel

        let mut gx = 0i16;
        let mut gy = 0i16;

        for ky in 0..3 { // loops over the kernel vertically
            for kx in 0..3 { // loops over the kernel horizontally
                let pixel = src[(y + ky) * pw + (x + kx)] as i16; // gets the pixel value
                let k = ky * 3 + kx; // kernel index

                gx += gx_kernel[k] as i16 * pixel; // convolves the pixel with the gx kernel
                gy += gy_kernel[k] as i16 * pixel; // convolves the pixel with the gy kernel
            }
        }

        let gx = gx as i32; // converts gx from i16 to i32 to prevent overflow in the magnitude calculation
        let gy = gy as i32; // converts gy from i16 to i32 to prevent overflow in the magnitude calculation

        let g = (gx * gx + gy * gy) as u32; // calculates the squared gradient magnitude
        let mut theta = (gy as f32).atan2(gx as f32).to_degrees(); // calculates the gradient direction
        if theta < 0.0 { // handles negative gradient directions
            theta += 180.0;
        }
        let theta = if theta < 22.5 || theta >= 157.5 { // maps the gradient direction to 0, 45, 90 or 135
            0
        } else if theta < 67.5 {
            45
        } else if theta < 112.5 {
            90
        } else {
            135
        };

        magnitude.push(g);
        direction.push(theta);
    }
```

**Why are we not taking the square root?** Notice that `g` is the _squared_ magnitude. Everything that uses the magnitude later (NMS and thresholding) only compares values, and squaring doesn't change which value is bigger. So skipping the square root saves one `sqrt` per pixel without changing the result. The only catch is that our thresholds must then be on the squared scale too, which I explain in the thresholding step.

**Why i16 for the sums and i32 for the squares?** Sobel's weights add up to 4 on each side, so with 8-bit pixels (0-255), |Gx| and |Gy| can be at most 4 x 255 = 1020. That fits easily inside an `i16`. But squaring 1020 gives 1,040,400, which would overflow an `i16` (max 32,767). That is why we convert to `i32` before squaring.

**Question: Why did we perform replicate padding and not something simpler like zero padding?** This is because standard zero padding adds a ring of 0 (black) pixels around the image. If the image edge is bright or textured, zero padding forces an unnatural, sharp drop to zero at the boundary, which a convolution filter reads as a fake high-contrast edge. Replicate padding copies the actual edge pixels outward, keeping the boundary smooth and continuous.

### 3. **Non-Maximum Suppression (NMS)**

In this step, we compare each pixel's magnitude with the magnitudes of its two neighbors along the gradient direction. If the pixel's magnitude is the biggest, it stays; otherwise, it is suppressed to 0. This thins the thick ridges left by the blur and the gradient calculation down to lines about one pixel wide. Example:

```txt
1  2  3
4  5  6
7  8  9
```

If 5 is a pixel's magnitude and its gradient direction is 0, we compare it with 4 and 6. If its gradient direction is 90, we compare it with 2 and 8. If its gradient direction is 45, we compare it with 1 and 9. If its gradient direction is 135, we compare it with 3 and 7.

(The y-axis of an image points down, so a gradient with positive Gx and positive Gy, which is 45 degrees, points toward the bottom-right.)

But before we perform this, we again have to pad so that the outermost pixels have neighbors. This time we pad with 0s, because a magnitude of 0 never beats a real magnitude in the comparison, so the padding can't change the result.

```txt
 0  0  0  0   0
 0  1  2  3   0
 0  4  5  6   0
 0  7  8  9   0
 0  0  0  0   0
```

```rust
#[inline]
fn zero_padding_u32(src: &[u32], width: usize, height: usize) -> Vec<u32> {
    let pw = width + 2;
    let mut slate = Vec::with_capacity(pw * (height + 2));
    slate.resize(pw, 0);
    for row in src.chunks_exact(width) {
        slate.push(0);
        slate.extend_from_slice(row);
        slate.push(0);
    }
    slate.resize(pw * (height + 2), 0);
    slate
}

#[inline]
fn zero_padding_u8(src: &[u8], width: usize, height: usize) -> Vec<u8> {
    let pw = width + 2;
    let mut slate = Vec::with_capacity(pw * (height + 2));
    slate.resize(pw, 0);
    for row in src.chunks_exact(width) {
        slate.push(0);
        slate.extend_from_slice(row);
        slate.push(0);
    }
    slate.resize(pw * (height + 2), 0);
    slate
}
```

```rust
    let magnitude = zero_padding_u32(&raw_magnitude, width, height);
    let direction = zero_padding_u8(&raw_direction, width, height);
```

**Why make two different zero padding implementations?** This is to reduce memory overhead. The magnitude holds the squared gradient magnitude. As we saw above, |Gx| and |Gy| are at most 1020, so the squared sum is at most:

2 x 1020^2 = 2,080,800

(Gx and Gy can't both reach their maximum at the same pixel, so this is an upper bound, but it is all we need.) This value needs 21 bits. That is too big for a `u16` (max 65,535) but fits comfortably in a `u32`.

The direction, on the other hand, only holds the values 0, 45, 90 and 135, which fit inside a `u8`. The labels themselves are arbitrary, as long as they are distinct. We could have used 0, 1, 2, 3 instead of 0, 45, 90, 135 and it would carry the same meaning.

Now that it is padded, we perform the NMS:

```rust
    let mut suppressed = vec![0u32; width * height]; // starts as all 0s; only local maxima get copied in
    for (i, out) in suppressed.iter_mut().enumerate() {
        let x = i % width; // column index
        let y = i / width; // row index

        let j = (y + 1) * pw + (x + 1); // index of this pixel inside the padded arrays
        let (a, b) = match direction[j] { // gets the two neighbors along the gradient direction
            0 => (j - 1, j + 1),
            45 => (j - pw - 1, j + pw + 1),
            90 => (j - pw, j + pw),
            _ => (j - pw + 1, j + pw - 1),
        };
        let m = magnitude[j];
        if m >= magnitude[a] && m > magnitude[b] { // keeps the pixel only if it is a local maximum
            *out = m;
        }
    }
```

**Why `>=` on one side and `>` on the other?**
If two neighboring pixels along the gradient have exactly the same magnitude, using `>=` on both sides would keep both of them and leave a line two pixels thick. Using a strict `>` on one side means exactly one of them survives.

Now we check whether the max magnitude is 0. If it is, the image is completely flat and has no edges, so we just output a black image and stop. This guard matters: without it, `t_high` would also be 0, so the check `value >= t_high` in the next step would be true for every pixel, and the flat image would come out as solid white "edges".

```rust
    let max_mag = *suppressed.iter().max().unwrap_or(&0);
    let mut edges: Vec<u8> = Vec::with_capacity(suppressed.len());

    if max_mag == 0 {
        edges.resize(suppressed.len(), 0);
        let image = GrayImage::from_raw(width as u32, height as u32, edges).unwrap();
        image.save("out.png")?;
        return Ok(());
    }
```

### 4. **Double Thresholding**

Now we pick two threshold values, a high threshold (t_high) and a low threshold (t_low). Pixels with a gradient magnitude higher than or equal to _t_high_ are marked as strong edges (255), pixels with a gradient magnitude less than _t_low_ are suppressed to 0, and the rest are marked as weak edges (127).

```rust
    let t_high = max_mag as f64 * 0.04;
    let t_low = t_high * 0.16;

    for &magnitude in &suppressed {
        let value = magnitude as f64;
        if value >= t_high {
            edges.push(255);
        } else if value < t_low {
            edges.push(0);
        } else {
            edges.push(127);
        }
    }
```

**A note on these numbers:** Because `suppressed` holds _squared_ magnitudes, the thresholds are on the squared scale too. `0.04` is 0.2^2, so `t_high` is 20% of the maximum gradient on the normal (linear) scale. `0.16` is 0.4^2, so `t_low` is 40% of `t_high`, which is 8% of the maximum gradient. If you want a threshold at a fraction `f` of the maximum gradient, use `f * f`.

**Note:**

- **The use of 255 and 127 is arbitrary. You are free to use your own numbers.**
- **t_high and t_low are free parameters. I am currently calculating them from the max magnitude, but you can set them to whatever you like.**

### 5. **Edge Tracking by Hysteresis**

Now, we check whether each weak edge is connected to a strong edge, either directly or through a chain of other weak edges, and convert the connected ones into strong edges. To do this, we check the 8 neighboring pixels of every strong edge for weak edges. If we find one, we convert it to a strong edge and push its index to the back of a queue so that we can check that newly added pixel's 8 neighbors too. In the end, any weak edges that were never reached are suppressed to 0 (black).

```rust
    let mut queue = VecDeque::new();
    for (i, &pixel) in edges.iter().enumerate() {
        if pixel == 255 {
            queue.push_back(i);
        }
    }
    while let Some(i) = queue.pop_front() {
        let x = (i % width) as isize;
        let y = (i / width) as isize;
        for dy in [-1isize, 0, 1] {
            for dx in [-1isize, 0, 1] {
                if dx == 0 && dy == 0 {
                    continue;
                }
                let nx = x + dx;
                let ny = y + dy;
                if nx < 0 || ny < 0 || nx >= width as isize || ny >= height as isize {
                    continue;
                }
                let j = ny as usize * width + nx as usize;
                if edges[j] == 127 {
                    edges[j] = 255;
                    queue.push_back(j);
                }
            }
        }
    }

    for pixel in &mut edges {
        if *pixel == 127 {
            *pixel = 0;
        }
    }
```

The algorithm is finished. Now we just need to convert this vector into an image.

### **Few key takeaways:**

- **Padding is a design decision, not a detail.** Replicate padding keeps the convolution from inventing edges at the border, while zero padding is harmless for NMS.
- **Skipping the square root is safe,** as long as everything downstream works on the squared scale. You just have to remember that when choosing thresholds.
- **Reasoning about value ranges pays off.** Knowing Sobel's output is at most 1020 in magnitude let me pick small integer types instead of defaulting to floats.
- **Hysteresis is just a breadth-first search** that starts from the strong edges and spreads through the weak ones.

### **Limitations of this implementation**:

- The sigma and the thresholds were tuned by hand for one image. There is no automatic way to choose them.
- The code is single-threaded and allocates several full-size buffers.
